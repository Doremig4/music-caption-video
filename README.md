# 자막 영상 생성기

`public/music.mp3`, `public/lyrics.srt`, `public/cover.jpg`를 교체한 뒤 실행.

```bash
npm run web
npm run preview
npm run render
npm run render:proxy
```

TXT 가사 자동 싱크는 최초 한 번 `npm run setup-whisper`를 실행한 뒤 웹에서 사용합니다.

`npm run web` 실행 후 `http://127.0.0.1:4173`에서 파일 업로드, SRT 편집, 렌더를 한 번에 할 수 있습니다.
완성 파일은 `outputs/music-video.mp4`에 저장됩니다. SRT는 UTF-8이어야 하며 마지막 자막은 음악보다 먼저 끝나야 합니다.

웹의 **출력 모드**에서 최종 영상(1920×1080) 또는 프록시(960×540)를 선택할 수 있습니다. 프록시는 자막 타이밍과 60fps를 유지하면서 해상도와 인코딩 품질을 낮춘 확인용 MP4이며, `outputs/music-video-proxy.mp4`에 별도로 저장됩니다. 터미널에서는 `npm run render:proxy`로 출력합니다.

자막은 모든 줄이 일정한 간격으로 함께 이동하며, 0.5초 동안 부드럽게 가속·감속합니다. 짧은 간격으로 자막이 이어져도 진행 중인 이동이 끊기지 않습니다. 현재 가사에서 위아래 두 줄까지는 선명하게 유지하고, 세 번째 줄부터 멀어질수록 점점 강하게 블러 처리합니다.

웹의 **배경 투명도**에서 뒤의 배경 이미지를 0~100%로 조절할 수 있습니다. 기본값 58%는 기존 배경과 동일하며, **기본값으로** 버튼으로 복원합니다. SRT 저장 또는 렌더 시 설정이 저장되어 최종 영상과 프록시 모두에 적용됩니다.

렌더링 준비 시 배경 블러를 한 번만 이미지로 처리하고, 화면에 보이는 자막 주변의 줄만 렌더링합니다. 최종 영상과 프록시의 해상도, 60fps, 자막 전환 및 블러 효과는 유지됩니다.

병렬 렌더링은 최대 5개로 설정되어 있으며, CPU 코어 수를 넘지 않습니다. 이 프로젝트의 10코어 Mac에서 5·6·8개를 반복 비교했을 때 차이가 작아 기본 5개를 유지합니다. 다른 기기에서는 `npm run render -- --concurrency=4`처럼 직접 조정할 수 있습니다.

웹의 **인코딩 방식**에서 표준 또는 하드웨어 가속을 선택합니다. 기본값은 기존 화질과 용량을 유지하는 표준입니다. 하드웨어 가속은 지원되는 기기의 인코더를 사용하며, 미지원 기기는 소프트웨어 인코딩으로 대체합니다. 하드웨어 가속의 목표 영상 비트레이트는 최종 영상 8Mbps, 프록시 2Mbps이며, 표준 출력과 화질 및 파일 크기가 달라질 수 있습니다. 이 프로젝트의 Mac에서 반복 비교는 하드웨어 가속이 더 느려 기본으로 활성화하지 않았습니다.

터미널에서는 `npm run render:accelerated` 또는 `npm run render:proxy:accelerated`로 하드웨어 가속을 비교할 수 있습니다. 두 방식 모두 기존 출력 파일 경로를 사용합니다.

병렬 처리 수를 다시 측정하려면 `npx remotion benchmark MusicCaption --codec=h264 --frames=2200-2559 --concurrencies=5,6,8 --runs=3`을 실행합니다. 짧은 음원은 프레임 범위를 음원 길이에 맞게 줄이세요. 하드웨어 인코딩 측정에는 `--hardware-acceleration=required --video-bitrate=8M`을 추가합니다.
