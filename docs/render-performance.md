# 병렬 처리와 하드웨어 인코딩 비교

2026-10-04, 이 프로젝트의 10코어 Apple Silicon Mac / RAM 16GB / Remotion 4.0.506에서 측정했습니다. 앞서 적용한 자막 범위 제한과 배경 블러 사전 처리를 포함합니다.

1920×1080, 60fps, 동일한 360프레임(2200~2559, 영상 6초)을 렌더링했습니다. 초기 준비 실행을 제외하고 각 조건을 3회 반복했으며, 아래 값은 프레임 생성과 인코딩을 포함한 시간의 중앙값입니다. 번들 생성과 메타데이터 준비 시간은 제외했습니다.

| 방식 | 병렬 처리 수 | 렌더 시간 |
| --- | ---: | ---: |
| 표준 H.264 (`libx264`) | 5 | 5.82초 |
| 표준 H.264 (`libx264`) | 6 | 5.90초 |
| 표준 H.264 (`libx264`) | 8 | 5.89초 |
| 하드웨어 H.264 (`h264_videotoolbox`, 8Mbps 목표) | 4 | 6.79초 |

병렬 처리 수 5·6·8의 차이는 약 1% 수준이고 측정 편차 범위에 가깝습니다. 5개를 기본값으로 유지합니다. 하드웨어 인코딩은 이 구간에서 표준보다 약 17% 느려 선택 옵션으로 제공합니다.

하드웨어 방식은 표준의 CRF 설정 대신 목표 비트레이트를 사용하므로 화질과 파일 크기도 달라집니다. 인코딩 방식 비교는 동일한 파일 크기 또는 동일한 화질을 보장하는 비교가 아닙니다. 전체 영상, 다른 음악·이미지, 다른 기기에서는 결과가 달라질 수 있습니다.

웹의 **인코딩 방식**에서 두 방식을 선택할 수 있습니다. 터미널에서는 `npm run render:accelerated`와 `npm run render:proxy:accelerated`를 사용합니다. 병렬 처리 수는 `--concurrency`로 변경할 수 있습니다. 측정 원본 JSON과 비교 영상은 로컬 `outputs/acceleration-check/`에 저장되며 Git에는 포함되지 않습니다.
